### 为什么蓝牙 RX 是 PA31 而不是 PA29

UART0 的 TX/RX 必须落在**同一组 pad** 上（MSPM0 的 PINCM 编号每 10 个一组，个位相同即同组）。这颗芯片在 LQFP-64(PM) 上实际可用的 UART0 引脚是：

| TX | RX |
| --- | --- |
| PA0 | PA1 |
| PA10 | PA11 |
| PA28 | **PA31** |

**PA29 根本没有 UART0 功能**——查器件数据（`deviceData/MSPM0G350X/MSPM0G350X.json` 的 mux 表），PA29 只有 `I2C1.SCL / UART2.RTS / TIMG8.CCP0 / TIMG6.CCP0`。PA0/PA1 被 OLED 的 I2C0 占用，所以除 PA10/PA11 之外唯一能用的就是 **PA28 + PA31**。SysConfig 对 PA28/PA29 组合会直接报错。

### 两个 GPIO 实例

拨码开关跨了 PA 和 PB 两个端口，而一个 GPIO 实例只能属于一个端口，所以在 syscfg 里拆成两组：

- `ADDR_SW_B`（PORTB）：`PIN_B26` = PB26、`PIN_B23` = PB23
- `ADDR_SW_A`（PORTA）：`PIN_A25` = PA25、`PIN_A23` = PA23

固件里 `Get_Device_Address()` 已按位分别指定端口，位序不变（bit0=PB26、bit1=PA25、bit2=PA23、bit3=PB23）。

### 方向速记

- M0 的 **TX (PA28)** → 蓝牙模块的 **RXD**
- 蓝牙模块的 **TXD** → M0 的 **RX (PA31)**

## 2. 继电器（PA7 / PA9）

**本工程配置为低电平有效（共阳）**：

- `3.3V` → `R1 470Ω` → AQY412 pin1（LED 阳极），pin2（阴极）→ `PA7` —— 充电支路总闸

## 3. OLED（PA0 / PA1 / PA16）

| 引脚 | 接法 |
| --- | --- |
| PA0 | OLED 模块 **SDA** |
| PA1 | OLED 模块 **SCL** |
| PA16 | P-MOS **栅极**（OLED 电源开关） |

### PA16 电源开关怎么接

```
   3.3V ──┬─────────────── S (源极)
          │                 ┌────────┐
        100kΩ               │  P-MOS │── D (漏极) ── OLED VCC
          │                 └────────┘
          └───── G (栅极) ──────┴──── PA16
```

- PA16 输出**低** → Vgs ≈ −3.3V → 导通 → OLED 上电（测量结束后才这样）
- PA16 输出**高** → Vgs ≈ 0 → 关断 → OLED 断电
- **栅极 100kΩ 上拉到 3.3V 是必须的**：复位后 PA16 是高阻，靠它把栅极拉到源极
  电位，保证 OLED 在复位期间也是关断的（否则 OLED 会在还没测量之前就偷电）。
- P-MOS 选**逻辑电平**、Vgs(th) 约 −1 ~ −2V 的（AO3401、Si2301 之类）。

### I2C 上拉

- SysConfig 里两个脚**没用内部上拉**（`onlyInternalResistor = false`），所以要
  **外部上拉**：SDA、SCL 各一个 4.7kΩ 到电源。
- 如果 OLED 模块板载已经有 4.7kΩ 上拉，就不要再加了。
- **建议把上拉电阻接到“开关之后的 OLED 电源轨”**，而不是常电 3.3V —— 否则
  OLED 断电时，3.3V 会经上拉电阻、再从 OLED 的 SDA/SCL ESD 二极管倒灌进去，
  把 OLED “虚供电”，断电就不彻底了。接到开关后的轨上，OLED 一断，整条总线就死了，
  而 MCU 侧在断电期间本来也不用 I2C，没影响。
- 程序里挂起看 `g_oled_addr`（0 = 总线上没人应答，多半是上拉/接线/供电问题）、
  `g_i2c_to_cnt`（>0 = 总线被拉住）。

## 4. 蓝牙模块（PA28 / PA31；PB13 可选）

### 4.1 接线总表（本工程当前配置：`BT_USE_DETECT_PIN = 0U`）

| 蓝牙模块（HC-04 等） | 接到 | 说明 |
| --- | --- | --- |
| **VCC** | **3.3V_BT**（7533-2 的输出） | **不要**接 M0 那片 7533 的输出，也不要直接接 Vcap |
| **GND** | **GND** | 和大电容 / 整流桥 / M0 共地 |
| **RXD** | ← **PA28** 经 `1kΩ` | M0 的 UART0 **TX**；RXD 脚对地再并 `10kΩ`（见 4.3） |
| **TXD** | → **PA31** | M0 的 UART0 **RX**；⚠️ 见 4.3，不处理会倒灌 |

- **必须交叉**：板子 TX → 模块 RXD，板子 RX ← 模块 TX。接反了一个字节都收不到。
- 参数：**115200 8N1**，两边都是 3.3V 电平。
- 模块 VCC 就近并 **0.1µF + 10µF**。

### 4.2 第二片 7533：让蓝牙一直有电（本次新增）

**核心：两片 7533 的输入取自不同的点。**

- 7533-1（给 M0）：输入接**迟滞电路的输出（节点 D）**。M0 一断电它就掉到 0 → M0 能真正关机。
- 7533-2（给蓝牙）：输入接**大电容 Vcap**（一直在 4~6.8V，从不掉到 0）→ 蓝牙一直有电。

```
     大电容正极 Vcap (4~6.8V, 一直在)
        │
        ├── 10µF ──┴── GND                     ← 输入去耦
        │
        └── 7533-2 的 IN
            │  HT7533  (TO-92 / SOT-89)
            │  pin1 = GND    pin2 = IN(Vin)    pin3 = OUT
            │
            OUT ──┬── 10µF ──── GND            ← 输出储能(不能省)
                  ├── 100nF ─── GND            ← 高频去耦, 放芯片脚边
                  └── 3.3V_BT ──┬── HC-04 的 VCC
                                └── 100nF + 10µF ── GND   ← 就放在模块 VCC 脚边
```

要点：

- **输入绝对不能接节点 D**（M0 那片 7533 的输入）。D 在迟滞关断时是 0V，蓝牙就跟着死了。
- **输入不要串限流电阻**。Vcap 最低会到 4V 左右，再串 100Ω 就把 7533 的输入压到
  dropout 以下，输出会跟着掉。要滤波就串 10Ω 或磁珠 + 10µF。
- HT7533 的 dropout 很小（10mA 时约 0.1~0.3V），所以 **Vcap ≥ 3.6V 就能稳出 3.3V** ✔
  这条很关键：M0 关机期间 Vcap 是 4V 左右，蓝牙照样有电。
- 两片 7533 的 GND 必须和 M0、大电容、整流桥**共地**（UART 才能通）。
- 蓝牙模块**不能接电池**：题目要求电路 A 的电能只能靠电磁耦合取。

### 4.3 M0 关机时的倒灌防护（★不做就会重现 1.6V 半死机★）

第二片 7533 让蓝牙"一直在电"，代价是：**M0 关机期间，HC-04 的 TXD 仍然是 3.3V 高电平**。
PA31 是 M0 的输入脚，M0 一断电，这个高电平就经 PA31 的 ESD 二极管灌进 M0 的 VDD 轨；
而 M0 那片 7533 只会"供"不会"吸"，泄不掉 → VDD 被抬到 1~2V →
**这就是你之前追了很久的"7533 输出 1.65V、M0 半死机、充不进电"**。

**做法一（推荐，0 元件）：TXD 不接。** 电流表只需要"往外发"，不需要收。
PA31 空着不动，倒灌路径直接消失。

**做法二（确实要收，最简单）：用一颗 2N7002 做"有电才通"的隔离开关。**

```
   HC-04 TXD ──────┬──── D   ┌── S ──┬── PA31
                   │    2N7002       │
                   │        G        [10k]
                   │        │         │
                   │        └─────────┴── 3.3V_M0   (M0 那片 7533 的输出)
```

（N-MOS：**源极 S 接 PA31 侧，漏极 D 接 HC-04 TXD 侧**，栅极 G 接 3.3V_M0；
 PA31 再经 10k 上拉到 3.3V_M0。方向不能接反。）

- M0 关机：栅极、上拉都是 0V → 管子关断，体二极管也是反偏 → **PA31 被 10k 拉到 0V，
  彻底断开，一点都灌不进去** ✔
- M0 开机：TXD 拉低时 Vgs = 3.3V → 导通 → PA31 = 0 ✔；TXD 拉高时管子关断，
  PA31 被 10k 上拉到 3.3V ✔。两个电平都能传，而且**不反相**。

**做法三（手边只有三极管）：NPN 射极跟随器。**

```
  HC-04 TXD ──[10k]── B    ┌── C ──── 3.3V_M0   (M0 那片 7533 的输出)
                           │  NPN  MMBT3904 / S8050
       PA31 ──┬─────────── E ┘
              │
            [10k]
              │
             GND
```

- M0 开机 → 跟随 TXD，高电平约 **2.58V**（M0 的 VIH = 0.7×VDD = **2.31V**，够用但有 0.27V 余量）
- 用**射极跟随器**是因为它不反相。用共射三极管或 PC817 光耦都会反相，
  UART 空闲电平就变成低电平了，错的。
- ⚠️ **它不如做法二干净**：M0 关机时集电极-基极结仍然正偏，基极电流会经集电极
  灌进 M0 的轨（约 **2.5µA**）。比"TXD 直接接 PA31"（>100µA，必挂）小两个数量级，
  但 2.5µA 仍可能把 M0 的轨顶到 1V 上下。**能换 2N7002 就换 2N7002。**

**PA28 那一侧也要处理**：M0 关机时 PA28 是高阻，HC-04 的 RXD 会悬空拾噪声，
模块会把这些噪声当数据发到 BLE 上去。所以：

```
  PA28 ──[1k]──┬── HC-04 RXD
               │
             [10k]
               │
              GND
```

✔ 只能**下拉到 GND**；**绝对不能上拉到 3.3V_BT** —— 上拉会经 PA28 倒灌进 M0，又是同一个坑。

#### 4.3.1 这些电阻可以用相邻标称值（E24 里随便挑）

**唯一有约束的是 PA28 那一路**：串联电阻和下拉电阻构成分压，串联电阻太大会把
RXD 的高电平压低。要求 `3.3V × Rpd/(Rpd+Rser) ≥ 2.6V`，即 **Rser ≤ 0.25 × Rpd**：

| 串联 Rser | 下拉 Rpd | RXD 高电平 | 结论 |
| --- | --- | --- | --- |
| 470 Ω | 10 k | 3.15 V | ✔ |
| **1 k** | **10 k** | **3.00 V** | ✔ 推荐 |
| 2.2 k | 10 k | 2.70 V | ✔ |
| 3.3 k | 10 k | 2.48 V | ✔ 勉强 |
| 4.7 k | 10 k | 2.24 V | ✗ 不行 |
| 1 k | 4.7 k | 2.72 V | ✔ |
| 4.7 k | 22 k | 2.72 V | ✔ |
| 10 k | 47 k | 2.72 V | ✔ |

- **串联那颗**：100 Ω ~ 2.2 k 都能用（它的作用只是限流保护，不是分压）。
- **下拉那颗**：4.7 k ~ 47 k 都能用（太小增加 PA28 负担，太大抗噪声差）。
- **精度无所谓**，5% 的碳膜/贴片都行，这里没有精密位置。
- **做法三（NPN）那两颗**：基极电阻和射极电阻要一起看 —— 规则是 **基极电阻 ≤ 2 × 射极电阻**，
  两颗都在 **4.7 k ~ 22 k** 里挑，输出高电平就都在 2.5 V 以上。
  （只换一颗会翻车：比如基极 100 k + 射极 4.7 k，输出只有 2.15 V，收不到。）
- **PA31 那一侧（做法二的 2N7002 上拉，或做法三的射极电阻）**：比 PA28 宽松，
  PA31 是 M0 的输入（高阻，漏电只有 nA 级），不存在"分压把高电平压低"的问题。
  - 2N7002 的 10 k 上拉到 3.3V_M0：**2.2 k ~ 47 k 都行**（别小于 1 k ——
    TXD 拉低时 3.3/R 全从 3.3V_BT 淌走，470 Ω 就是 7 mA，和蓝牙本身一个量级了）。
  - 上升时间不用担心：47 k × 10 pF = 0.5 µs，远小于 115200 的 8.7 µs 位宽。
- ⚠️ **但 PA31 不能靠"串电阻"解决倒灌**：串 1 k 还有 2.7 mA，串 10 k 还有 270 µA，
  串 100 k 还有 27 µA —— 每个都够把 M0 的 3.3 V 轨顶到 1 V 以上。**只能靠断开/隔离**
  （做法二、做法三），或者干脆不接 TXD（做法一）。
- **电容也能换相邻值**：10 µF → 4.7 µF / 22 µF 都行；0.1 µF 就是 **104**（100 nF）。

### 4.4 PB13（在位检测）—— 不接也行

- `ccs_empty_B.c` 里 `#define BT_USE_DETECT_PIN 0U` 表示**不用 PB13**，
  `bluetooth_present` 直接置真，UART 一直可用。
- 想改回 5 线接法（插上模块才开 UART 省电）：模块侧引一根线到 **PB13**，
  模块插上时把 PB13 **短到 GND**，同时把 `BT_USE_DETECT_PIN` 改成 `1U`。
- ⚠️ **不接 PB13 却忘了把宏改成 0**：PB13 内部上拉，悬空读到 1 → 判成“没插模块”
  → `DL_UART_Main_disablePower()` 把 UART 断掉 → **蓝牙一个字节都发不出去**。
- PB13 空着不接任何东西没有副作用（输入 + 内部上拉，几乎不漏电）。

### 4.5 和 XDS110 抢线

PA28 / PA31 在 LaunchPad 上默认接到板载 XDS110 的虚拟串口。接蓝牙模块前，
把对应的 **RXD / TXD 跳线拔掉**，否则两边会互相打架（收不到、或者发出去被吃掉）。

### 4.6 先算账：蓝牙常开要多少输入电流

蓝牙的每一毫安都得从大电容里出，而大电容只能靠 CT 取电。用 `设计说明.md`
第 6 节的取电表（3.3V 侧可用电流）：

| 一次侧电流 I1 | 3.3V 侧可用电流 |
| --- | --- |
| 0.1 A | 0.67 mA |
| 0.2 A | 2.02 mA |
| 0.3 A | 3.20 mA |
| 0.5 A | 5.48 mA |
| 1.0 A | 11.08 mA |
| 2.0 A | 22.25 mA |

整机能维持工作的条件是 **可用电流 > 蓝牙平均电流 + M0 的耗电 + 给大电容充电的余量**：

| HC-04 平均电流（3.3V 侧） | 能维持的最小 I1（估） |
| --- | --- |
| 1 mA | ≈ 0.2 A |
| 3 mA | ≈ 0.4 A |
| 5 mA | ≈ 0.5 A |
| 10 mA | ≈ 1.0 A 以上 |

**所以第一件事是量 HC-04 的 VCC 平均电流**（万用表 mA 档串进 VCC 线，数字表会把发射尖峰平均掉）：
没连接（广播态）量一次，连上手机后量一次。

如果测出来 >5 mA，那"蓝牙常在线"和"0.1 A 能启动"就是**物理上互斥**的 ——
蓝牙要的功率比 0.1 A 时整个系统能取到的还多。这时只有三条路：

1. **把 HC-04 的平均电流压下去**（首选）。若它兼容 HM-10 的 AT 指令集，先发个 `AT`
   看回不回 `OK`，然后 `AT+ADVI` 把广播间隔拉到 1~2 s，能省一大截。
2. **接受启动电流被抬到 0.5~1 A**（"启动电流越小越好"那部分分基本放弃）。
3. **回到"蓝牙间歇开窗"**：不给蓝牙独立常供电，让 M0 活着时蓝牙才在。

### 4.7 报文格式

蓝牙挂在 7533-2 上一直有电，所以 **连接是常连的**：M0 每上电测一次、发一帧，
读表器按内容去重即可。单次模式（`ALWAYS_ON_MODE = 0`，默认）下 M0 断电前会
把同一帧每 50 ms 重发，一直发到断电；常开模式（改成 `1U`）下每 5 s 发一帧。

```
$T,03,0.1456,0,77\r\n
 │  │   │    │  └─ 校验: 从 '$' 到 status 为止所有字节异或, 两位大写十六进制
 │  │   │    └──── 状态: 0=正常 1=低限(<0.2A) 2=超限(>2A) 3=数据无效
 │  │   └───────── 一次侧电流有效值 [A], 4 位小数
 │  └───────────── 4 位拨码开关设定的地址 00~15
 └──────────────── 帧头（读表器只认这个）
```

## 5. 采样前端（PA15）

- PA15 = ADC1 通道 0，接在 20Ω 采样电阻上，**直流偏置 1.65V**（VDDA/2）。
- 输入范围必须落在 **0 ~ 3.3V** 内：20Ω 上的交流电压在 2A 时约 1.0V（有效值），
  骑在 1.65V 上正好不顶不撞。
- 前面建议加 RC 抗混叠（例如 1kΩ + 100nF），并且采样节点用**星形地**单独回。
- 程序里挂起看：`g_v_dc`（应约 1.65V，是 0 说明偏置没建立）、`g_v_rms`
  （2A 时应约 1.0V）、`g_c_min / g_c_max`（贴 0 或 4095 说明削顶）。

## 6. 拨码开关（PB26 / PA25 / PA23 / PB23）

| 引脚 | 位 |
| --- | --- |
| PB26 | bit0 |
| PA25 | bit1 |
| PA23 | bit2 |
| PB23 | bit3 |

- 4 位拨码开关，**每位一端接引脚、另一端接 GND**，内部上拉已在 SysConfig 里打开，
  **不需要外部电阻**。
- 开关**闭合（ON）** → 引脚被拉到 GND → 读到 0 → 该位 = 1（代码里判断的是
  `readPins(...) == 0`）。
- 地址范围 0~15，作为蓝牙报文里的地址字段（`$T,aa,...` 的 `aa`，屏上不显示）。

## 8. 没用到的引脚

- SysConfig 只分配了上表这些，**其余引脚本固件全都没用**，可以自由分配给别的功能。
- TI 建议不要把不用的脚悬空：配成**输出低**，或者**输入 + 内部上/下拉**。
- 在 LaunchPad 上，有些引脚默认接着板载 LED / 按键 / 温度传感器 / 光传感器，
  要用之前先拔掉对应跳线。
